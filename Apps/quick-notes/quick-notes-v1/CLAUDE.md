# Ayran Quick Notes

Let's create an quick notes app using Tauri that stores everything in the embedded browser's indexedDb (and webStorage where it makes sense). The app should have a top header visible at all times and the rest of the content should be scrollable. When the user first opens the app, a button for "create your first note" should sit in the center of the screen. After that, there will still be a plus button in the top bar for creating a note. Along the create new note button, in the top bar there should be an options button with the following options:
 - Select all notes

So yes, note items should be selectable from this list of notes view. Otherwise, notes will be editable. The default order of showing the notes is last created first. Our note system should be based on markdown. So the contents of a note should be stored as plain text and (when the user chooses) a markdown preview should be shown based on the markdown text of the current note. The title of the note used in the list of notes should be derived from the note's markdown contents (our app should look for the markdown primary heading every time the user saves a note, store that title in indexedDb along the note item and display it as such in the notes list or display an italicised placeholder that reads "untitled note"). When entering the edit mode for a note, we should still have the top bar where the add note button will no longer be shown and the options for the options button will be the following:
 - a "snap select" submenu entry that has the following sub entries:
   - "whole paragraphs": this option will replace the current text selection with one that fully selects all the paragraphs that are currently either partially or fully selected. Note that the replacing selection will not include leading or trailing whitespaces (just the actual paragraphs). Along with actual paragraphs, any other types of blocks that are partially or fully selected will likewise be fully selected in the replacing selection: headings, rules, tables, code blocks (but not quote blocks, let's treat the contents of quote blocks directly in this case). About html elements embedded inside the markdown: let's treat every leaf html element like we treat paragraphs and every parent html element like we treat quote blocks: only fully select its partially selected children (and of course the starting tags).  
   Note: maybe when having text selected, if pressing a button makes the selection disappear before the javascript handler is executed, let's try to find a way to keep track of the text selection all the time, so that when the user clicks the option button, our app remembers what text was selected just before the user clicked the options button.
