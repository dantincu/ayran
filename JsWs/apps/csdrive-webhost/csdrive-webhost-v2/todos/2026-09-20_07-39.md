## About huge directory listings

How do we handle cases when the directory listing itself is too big for our app's internal memory resources? What would such a situation look like? Say the average entry name is 20 characters long and contains mostly ASCII characters with ocasional unicodes. How many entries in one folder will become problematic? How about when the average entry name is 100 characters long and most names are chinese names or mostly non ASCII unicodes?

Is there a way to retrieve just a list of ids for entries of a folder? Then if we only have the ids, we can retrieve metadata in chunks.

## New features

1. Everywhere we have tags: only show the row of tags if at least one tag has been added. When no tag has been added (or all of them were removed) there should be an option to add tags from the details popup modal for that record (all our listings should have a details popup model for each record).

2. In the system apps tab page add an option to group records by root. In this mode the root will no longer be visible under each record.

3. Let's optimize our listings for mobile and other slim width situations even further: make the row of action buttons fall bellow the rows of text and tags if the width of the window is slim.

4. All our text editors (and single line textboxes) should have 3 options:
   - select paragraphs (or select all for single line textboxes): will select the paragraph(s) that is partially selected (or where our text cursor was the last time the editor was focused) entirely while discarding trailing and leading whitespaces (trailing whitespaces after the last paragraph and leading whitespaces before the first paragraph).
   - copy to internal clipboard (our app's own internal clipboard mechanism that will only be able to hold text - that is a string - that will be available globally - that is accross all secondary windows and the main window / admin app) will copy the text from the current text selection to internal clipboard
   - paste from internal clipboard will replace the text from the current text selection with the text from the internal clipboard
   - copy to clipboard - will copy the text from the current text selection to OS clipboard
   - paste from clipboard will replace the text from the current text selection with the text from the OS clipboard

5. All our file managers will give the option for seeing the details of a folder or file in a popup modal and there the path should be visible along with options to copy to OS clipboard / internal clipboard. Same rule applies to Filen explorers (and besides the path, there should also be an option to view/unhide the item id and copy it to OS clipboard / internal clipboard). For folder listings there should be away to update the path (paste it from OS clipboard or internal clipboard in a popup modal textbox to navigate to the new path).
