# Ayran Sudoku Simulator Tauri App

I want to create a tauri app (both for mobile and desktop) for a sudoku gameplay simulator. We're not going to generate sudoku starting numbers but the player will start with a blank board and add whatever numbers they want and the app should prevent them from entering conflicting numbers (same number in the same group or row or column). The app should also be able to import sudoku boards from a printscreen image (users will crop the actual board from their screens so the OCR library should only parse numbers and the places they appear on the grid).

Next, here are some features our app will offer during game play. At any point the user should be able to save a snapshot of the current board (and give that snapshot a name - the default of which should be the coordinates of the last input number and the number itself). Multiple snapshots can be saved. Reverting from the current state to a saved snaphot should always be possible. Snapshots naturally inherit from one another, so when viewing the saved snapshots, instead of a mere list let's show a tree view (static, no collapse/expand buttons). Deleting saved snapshots should also be possible (deleting a snapshot that contains children will also delete all of its children recursively with full depth, and if the current state is itself a continuation of one of the deleted snapshots, the state of the board should be reverted to that of the nearest ancestor snapshot). There should also be a possibility to assign a colored label to any snapshot (and that will be visible in the tree view).

Regarding theming: the app should only come with light mode. Dark mode will only be supported for individual cells (that is the user can turn any cell to dark mode). For dark mode cells the user can also change their background colors (let's have some predefined colors and give the user the possibility to define, save, and delete custom colors). The dark mode and background colors for individual cells should be saved as part of any snapshot.

Finally, state of the app should be persisted on indexedDb.
