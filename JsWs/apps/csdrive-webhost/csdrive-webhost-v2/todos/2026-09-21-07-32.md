1. All the constants I ever mentioned about folder pairs and notes should be put in a config file that will be included in the app bundle / installer file.

2. In the Notes File Manager let's add the option to "Add Folders Pair" which will give the user the option to choose a custom index and even the entire short folder name (any string allowed as a folder name). This will include the .keep file inside the full folder name. In the dialog box for creating the pair there will be the title textbox. Instead of simply dissalowing invalid path chars, strip them from the full name dir upon creation, just like we do when we create notes (and show an icon hint that displays invalid path chars). Also show a checkbox for creating a markdown file inside the short folder name (just like we do when we create notes).

3. The Notes File Manager and Note Files Explorer should allow easy file and folder (and note) renaming the way Total Commander does: a keyboard shortcut (or the regular mouse/touch way to trigger it) for renaming an item, then pressing the up or down keyboard arrow will both submit the renaming and advance to the prev/next item in the list. Offer the same approach when editing note indexes (I think I did mention that we need to allow direct editing of note indexes and even display them by default. We should have a popup modal that lets us reassign indexes for all child notes of a parent note and then when the user submits, it performs that operation once for all child notes). Also, we should offer the functionality to normalize child note indexes (respecting the index intervals where they currently sit). Also, let's offer options to "convert a note's index" from one interval to another. This should be done inside the mass index reassignment popup modal. Also, when moving / removing child notes, give the option to normalize the indexes of remaining notes after completing the move / remove operation. Also, when moving / copying notes under a different parent note, by default we'll assign them the next available indexes from the new parent note. But also give the option to assign custom indexes (fill gaps in the parent note).

4. Regarding reassigning note indexes: besides manually editing the numbers, let's offer a classic reordering functionality like we do everywhere else in our app's lists: through drag and drop and with top arrow buttons. I think its easiest to combine all these index-related operations in one popup modal: manual reassignment of indexes, index interval conversion, index normalization, reordering through drag and drop and top arrow buttons. NOTE: if it's too difficult to automatically reassign indexes when dragging and dropping or moving with top arrow buttons, then simply recalculate all indexes for all child notes of the parent note upon any classic reordering operation (without submitting it instantly, of course).
