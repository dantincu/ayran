Regarding the text editor: now there's an occasional flicker when I'm typing and I think that's due to completely rerendering the editor DOM (I remember you said you were using the dangerouslySetInnerHtml attribute to inject the rendered html). If this completely rerenders the DOM everytime our worker finishes recalculating the code highlighting, that must be the reason for the flicker. In this case, let's create an "experimental code editor" for which the user will be able to opt in as a setting item from the admin app. This experimental code editor will bypass the react rerendering completely and not use dangerouslySetInnerHtml attribute at all. Instead, we'll need to recreate the DOM in memory (that will not attached to the real DOM), then do a live diffing between the new detached DOM and the live real DOM and just make the necessary substitutes. Does this sound like it could remove the flicker and not cause other issues? Yes, I'm aware that it is a huge architectural change, so let's have a discussion about this.
