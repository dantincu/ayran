# Ayran Mailbox (Tauri)

The Ayran WebMail client (`../ayran-webmail-client`) as a desktop and mobile app: Gmail, Outlook and Yahoo,
read / compose / reply / forward, images blocked unless the sender is trusted, folder tree, search, sort,
group by sender, paginated list with the lazy page picker.

## Layout

| | |
|---|---|
| `src/` | The React UI, carried over from the web app. Only the service layer changed: `services/emailService.ts` calls Tauri commands instead of the Express API. |
| `src-tauri/src/lib.rs` | The commands the UI calls, app state, token refresh. |
| `src-tauri/src/accounts.rs` | Connected accounts, one folder pair each, credentials encrypted. |
| `src-tauri/src/secure_store.rs` | AES-256-GCM files keyed by a random key held in the OS key store (from CsDrive WebHost). |
| `src-tauri/src/oauth.rs` | Gmail / Outlook sign-in: authorization code + PKCE with a loopback redirect (RFC 8252). |
| `src-tauri/src/mail/` | `gmail.rs` (Gmail REST), `outlook.rs` (Microsoft Graph), `yahoo.rs` (IMAP + SMTP), shared `types.rs` and helpers in `mod.rs`. |
| `src-tauri/src/folder_pairs.rs` | The folder pairs strategy (copied from CsDrive WebHost). |
| `src-tauri/gen/android/` | The Android Studio project (generated by `tauri android init`, plus `SecureKey.kt`). |

## How credentials are kept

- **They never reach the webview.** The UI names an account by id; the Rust side reads the account's
  tokens or app password, refreshes tokens when needed, and talks to the provider itself.
- **At rest they are encrypted.** Each account is `<app data>/accounts/NNN/account.enc`, AES-256-GCM
  (`nonce || ciphertext+tag`, written atomically). Beside it, `NNN-<provider>@@<email>/.keep` says which
  account `NNN` is (folder pairs strategy).
- **The key belongs to the OS.** One random 32-byte key, created on first use, kept in:
  - Windows: Credential Manager (`ayran-mailbox-tauriapp` / `app-encryption-key`);
  - macOS: Keychain; Linux: Secret Service (via the `keyring` crate);
  - Android: wrapped by a non-exportable Android Keystore AES key (`SecureKey.kt`, called over JNI);
  - iOS: **not implemented yet** — `secure_store.rs` refuses with a clear error rather than store the key
    unprotected (needs the iOS Keychain in `platform::resolve_key`; can only be built on macOS).
- Removing an account deletes its folder pair.

## Setup

1. `npm install`
2. Register the OAuth clients and put their ids in `.env` (copy `.env.example`). They are compiled into the
   app by `src-tauri/build.rs`; a build without them still runs, and says what's missing when you try to sign in.
   - **Google**: Cloud Console → Credentials → OAuth client ID → *Desktop app*. Enable the Gmail API.
     Loopback redirects need no registration.
   - **Microsoft**: App registrations → Authentication → *Mobile and desktop applications*, redirect URI
     `http://localhost`. Set `OUTLOOK_TENANT` to match the account types the registration accepts
     (`consumers` by default).
   - **Yahoo**: nothing — users connect with an app password from their Yahoo account security page.

## Run and build

- Desktop dev: `npm run tauri dev`
- Desktop release: `npm run tauri build`
- Android (needs `ANDROID_HOME`, `NDK_HOME`, JDK 17 as `JAVA_HOME`):
  `npm run tauri android build -- --debug --target x86_64 --apk` (or `aarch64` for phones)
- Rust tests: `cd src-tauri && cargo test` (two of them use this app's real key-store entry, as the app does,
  but only temporary folders)

## Changes from the web app

- The Express server is gone; its logic is in Rust. Sign-in opens the system browser and the app waits
  (with a Cancel button) instead of redirecting the page.
- Message HTML gets its own Content-Security-Policy: no remote content at all unless the sender is trusted
  (the old `<img>` rewrite missed CSS backgrounds and single-quoted sources). Links open in the system browser.
- Replies now carry the original's real `Message-ID` in `In-Reply-To` / `References` (they used the provider's
  internal id), so they thread in other mail clients.
- Search: To matches To, Cc or Bcc; body text is searched on Gmail and Yahoo, and on Outlook through Graph's
  `$search`. Gmail page tokens are cached, so jumping to page N no longer costs N requests each time.

## Known limits

- **Regex search** is applied to the page the provider returned (no provider searches by regex), so a page
  can show fewer than 50 matches and the total is the provider's count for the non-regex criteria.
- **Outlook body search** returns Graph's best matches, sorted locally; it doesn't page beyond the first page.
- **OAuth on mobile** uses the same loopback redirect. It works while Android keeps the app alive in the
  background during sign-in; a custom-scheme / app-link redirect would be sturdier and is not done yet.
- Not tested against live accounts in this build: there were no OAuth client ids or test mailboxes. The
  desktop app was launched and the Android APK built; the protocol pieces (PKCE, loopback listener, MIME
  building, search queries, encryption, account storage) are covered by unit tests.
