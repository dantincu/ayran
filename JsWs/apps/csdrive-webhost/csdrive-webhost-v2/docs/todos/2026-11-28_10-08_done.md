1. Regarding the JS Playground feature:
   - each time the user-provided code is executed, the inserted script tag should replace the previously inserted script tag, instead of simply append after it
   - the way to print stuff from the user-provided code should be by overriding the console object (or all of its methods) and mimick its functionality from the browser debugger tools to our area
   - this js playground should be able to execute certain pieces of javascript code whenever a new playground is opened (similar to powershell scripts are executed when a new powershell console is opened). This should be achieved through a set of configurable profiles, where each profile has a name and an associated javascript code (saved as a string and itself editable from a code editor). Both the initializing code and the user-provided inline code should themselves be able to execute javascript code from a string (similar to using javascript's built-in eval function) and such javascript code should also be executed by replacing the currently executing script tag with a new one containing the javascript code provided as string. And given that both the initializing code and the user-provided inline code should have the exact same rights the notes app has, they should be able to load contents of any file as string, including javascript files, so in essence be able to load and execute javascript from external files.
